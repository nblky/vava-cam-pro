# 实时观看与画质

当前使用原固件摄像头 → Agent → 自有 CoAP / DTLS UDP → Server → 浏览器的链路。摄像头输出 H.264 / AAC；Server 用 MP4 / fMP4 供浏览器播放。连续出口复制 H.264 视频，8 kHz AAC 适配为浏览器可用的 48 kHz AAC。Agent 不运行 FFmpeg，也没有使用原厂 P2P。

## 观看与本机录像

点击概述中的摄像头封面打开弹窗并开始观看。名称不触发播放，主导航没有独立的“实时观看”。停止按钮取消媒体接收并释放本次观看租约，不是单纯暂停 video 元素。关闭弹窗与退出会收尾本机录制及观看连接。

直播没有固定 120 秒或三分钟截止；断线、无媒体、慢消费者、会话失效仍会释放资源。绿色 LIVE 表示正在观看。只有点击“录像到本机”才开始记录之后接收的音视频，红点与独立计时表示正在录制；停止后下载到观看设备，不创建基站或云录像。关闭观看只会收尾已经主动开始的录制。

本机录制要求稳定编码参数；录制时不主动切档。外部变参时保存可解码完整前缀，不静默继续拼接不兼容的参数或自动开始下一段。

## 画质与自动策略

| 菜单 | 摄像头档位 | 已核验实际尺寸 |
| --- | --- | --- |
| 1080P | 0 | 1920 × 1080 |
| 720P | 1 | 1280 × 720 |
| 360P | 2 | 640 × 360 |
| 自动 | 观看端策略，不发送档位 3 | 根据当前实际解码档位调整 |

自动放在菜单最后。它从当前实际档位开始，不固定先切到流畅。每 4 秒采样缓冲、播放推进、卡顿和丢帧；连续两次播放良好可升一级，连续两次较差可降一级。开始观看、重新选自动、切档成功后有 8 秒观察期，其间不自动切档；五分钟窗口最多三次自动调整。录制、页面隐藏、暂停及切档过程中暂停策略。实际阈值以 [createAdaptiveQuality](../vava-server/web/management.js) 为准，不是对原厂自动算法的等价承诺。

下发成功或收到回显不等于画质切换完成。播放器要确认实际目标尺寸帧；浏览器支持时以 `requestVideoFrameCallback` 验证呈现。

## 连续切档

Agent 的 `continuous_quality` 默认 0，仅 `VA-HS03 / 1.4.0.54` 的已验证组合允许启用：

```sh
uci set vava-agent.main.continuous_quality='1'
uci commit vava-agent
/etc/init.d/vava-agent restart
```

需要 Server 构建时检测到 FFmpeg 5+ 开发库且未关闭 `VAVA_LIVE_AV`，并由两端协商能力。没有该能力时仍走停止本次流、等待空闲、写设置、重新连接的兼容路径，会有短暂停顿。

连续路径保留摄像头观看需求、DTLS 租约和认证 HTTP 连接。连接 generation 与 codec epoch 分离；新 SPS / PPS 只在匹配 IDR 时提交。Server 更新 MP4 初始化段，音频编码器继续运行；浏览器优先在原 SourceBuffer 重配，不支持时仅替换 MediaSource。

限制：每台摄像头一个远程观看者；要求 SN、slot、revision、租约所有权及已验证固件。事件录像活动/收尾时等待，最长 90 秒；已发的写操作不自动重放。编码路径只接受已验证 I/P 渐进流，不猜测 B 帧 DTS。已知流的 SPS 无重排声明由 Server 在封装中规范化，不改变摄像头视频像素。

## 抓图、封面与对讲

抓图读取当前观看帧。最后观看封面只在浏览器内存中保留，刷新后可回退至已有事件短片封面；状态轮询不会定时重建图片，也不为封面唤醒摄像头。

对讲有软件链路，但浏览器需要受信任 HTTPS、麦克风权限、`AudioEncoder` / `AudioData` 和 8 kHz AAC 编码能力。编码器不支持时明确失败，不把数据排队成功当作真实扬声器已发声。

## 已验证范围

- 合成测试覆盖六方向切换、独立解码与像素核对、连续音频时间戳、参数代次、截断和时钟错误。
- DTLS 模拟测试覆盖租约所有权、SN / generation、唯一观看者和事件录像门控。
- HomeWRK 记录中同一次观看完成六方向切换，约六分钟 3683 帧丢一帧，实际尺寸匹配；真实本机 MP4 音视频完整解码有记录。
- 更多浏览器、数小时播放、复杂丢包/抖动、PIR 与切档瞬间竞争及真实对讲发声仍待验。
