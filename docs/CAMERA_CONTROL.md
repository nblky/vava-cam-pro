# 摄像头配对与配置

功能验证状态见 [FEATURES](FEATURES.md)。本文说明当前产品语义；未验收的硬件效果不会因为有配置项或收到回显而自动变成“已通过”。

## 配对

在 LuCI“摄像头配对”或 Server“基站设置 → 摄像头配对”打开窗口。请求 120 秒，临时热点准备完成后显示实际倒计时；让摄像头进入配对模式。临时 2.4 GHz SSID 为 `VAPair-` 加所配置原基站 SN 的后八位。随后下发正式专用 AP 信息，等待原摄像头正式连接、身份登记与确认，成功后关闭临时 AP。

同一任务再次打开只查看进度，不重新计时。取消后等待基站确认热点关闭；失败保留错误及重试入口。最多登记四台。配对任务持久进度可用于重启后的保守恢复，不以弹窗倒计时推断热点必然已关闭。

**当前没有配对后完整工作模式选择向导。** 新配对使用兼容的持续布防/中灵敏度策略，摄像头工作模式沿用其已有状态，不自动发送完整的续航或监控预设。配对后应在摄像头设置中明确保存工作模式。生产与 `--diagnostic-defaults` 的测试默认值不同。

## 保存、下发、回显与效果

1. Web 保存期望值到基站；普通设置、策略与名称分别有独立 revision。
2. Agent 根据摄像头连接、媒体空闲、型号与报告决定是否下发，逐条串行执行。
3. 显示等待、已发送、匹配回显、超时或需手工重试。离线时保存成功不等于已送达。
4. 实际画面或设备行为必须另行验收。未知报告值保留为未知，不回写猜测默认值。

所有摄像头请求应绑定完整 SN 与当前槽位；更新同时传入对应域 revision。身份变化返回 `camera_identity_changed`，配置冲突返回 `configuration_conflict`，不覆盖并发修改。普通配置保存在 Agent 的 `settings.bin`，策略在基站策略文件，名称在 `profiles.bin`；不是频繁覆盖一份包含电量的 JSON。

`configure-many` 对基站文件是整组校验和提交；摄像头逐条下发无法提供原子回滚。重启保留期望值，但清除连接/回显进度；需要显式重试的操作不自动反复写摄像头 Flash。

## 工作模式与计划

| 模式 | 下发模式值 / 灵敏度 / 再触发间隔 / 短片时长 |
| --- | --- |
| 最佳续航 | `0 / 2 / 20 / 10` |
| 最佳监控 | `1 / 1 / 0 / 20` |
| 自定义 | 模式 2；灵敏度高/中/低为 1/2/3；间隔 5–120 秒；短片 5–60 秒，时间字段为 5 秒步长 |

这些是当前程序的参数映射；真实触发计时和功耗仍待验。工作模式是灵敏度权威来源，撤防发 0，重新布防恢复模式档位。没有已保存工作模式时使用兼容策略档位，不通过计划覆盖模式灵敏度。

每周计划最多十条，支持逐条启停、全天与跨午夜、固定时区偏移。基站时钟不可信时计划保持撤防；固定偏移不等于带夏令时的时区数据库。

事件短片默认跟随当前连接有效工作模式报告或匹配回显的长度；没有可信报告时回退 10 秒。另有基站指定时长策略，两者是不同来源，不是叠加两个硬上限。`recording.duration_source` 与 `duration_seconds` 才是该次任务采用的长度。120 秒再触发间隔不是直播时长上限。

## 其他设置

图像翻转、夜视、防闪烁、画质、OSD、扬声器音量和播放音频门控均有持久写入链。OSD 的真实枚举仍存在未核实值；音频播放门控不等于浏览器静音，也不等于关闭摄像头麦克风。

检测框写入只开放已核实的 `VA-HS03 / 1.4.0.54`，需要当前连接有效的算法报告及媒体空闲；它不提供独立 PD / FD 算法开关或区域编辑。直播切档另走 [受租约保护的画质流程](LIVE.md)，不能绕过型号和录像门控。

## 恢复、删除与改名

| 操作 | 当前意图 | 录像处理 |
| --- | --- | --- |
| 重命名 | 修改基站本地名称，不唤醒摄像头 | SN 与历史目录不变 |
| 恢复摄像头出厂设置 | 独立发送已分析的本地恢复命令，清理普通参数覆盖，保留登记和基站策略 | 保留全部历史片段 |
| 删除摄像头 | 先恢复/清除配对并跟踪结果，再移除登记；离线或结果不明需明确处理 | 保留历史片段及可按 SN 访问的身份 |

恢复与删除的状态机及主机测试已实现，**真实设备最终行为未完成验收**。摄像头离线时不能把“已发送”描述成“恢复成功”。管理员应核对摄像头提示与重新配对结果。详见实现 [removal.c](../vava-station/src/removal.c) 和测试 [sdk_removal.py](../tests/sdk_removal.py)。
